A naive approach multiplies $x$ exactly $n$ times, running in an inefficient $O(n)$ time loop.To pass technical interview performance bounds, you must use Binary Exponentiation (also known as exponentiation by squaring) to reduce the complexity to $O(\log n)$. The logic cuts the problem in half at each step:$$x^n = \begin{cases} (x^2)^{n/2} & \text{if } n \text{ is even} \\ x \times (x^2)^{(n-1)/2} & \text{if } n \text{ is odd} \end{cases}$$ExamplesExample 1:Input: x = 2.00000, n = 10Output: 1024.00000Example 2:Input: x = 2.10000, n = 3Output: 9.26100Critical Edge Cases to PassNegative Exponents: If n is negative (e.g., $n = -2$), the math changes to $\frac{1}{x^{-n}}$. The algorithm must invert the base $x = \frac{1}{x}$ and flip the sign of $n$ cleanly.Integer Overflow at Min Boundary: In 32-bit signed architectures, the minimum possible integer is -2147483648. If you try to flip its sign to positive (-n), it will overflow because the maximum positive signed 32-bit integer is 2147483647. You must store the exponent in a 64-bit container (long or long long) before changing its sign.Base Zero and One Values: Subtleties like $0^n$ must return 0 (for positive $n$), and $1^n$ or $x^0$ must evaluate to 1.0 instantly.
